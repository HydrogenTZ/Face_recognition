# ESP32-P4 人脸识别首轮实验记录

日期：2026-11-09。这是本次上板实验的记录，不代表完整的识别精度评估。

## 实现与运行条件

- 开发板：Waveshare ESP32-P4-WIFI6-Touch-LCD-3.5；COM3 连接 CH343 串口。
- esptool 实际探测：ESP32-P4 芯片 v3.2；启动日志：CPU 400 MHz、32 MB PSRAM、PSRAM 200 MHz、Flash 16 MB。
- ESP-IDF v6.1；ESP-DL 3.1.3；人脸检测 MSR/MNP；特征提取 MFN_S8_V1，512 维归一化特征。
- 模型源：乐鑫官方 human_face_recognition 0.2.0 组件，作为本地组件固定并适配 ESP-DL 3.1.3 的数据库 API。
- 本程序使用独立 NVS 存储人员特征，自行执行特征点积查询；每人首轮一条特征。
- 实际摄像头输出：800×800 RGB565（启动日志中的 VIDIOC_G_FMT）。不能将 sdkconfig 中同时启用的 1280×960 支持项误认为实际当前输出。
- AI 输入：预览中心正方形缩放为 240×240，按当前镜头安装方向逆时针旋转 90°，再检测、按五个关键点对齐、提取特征。
- Debug 编译优化；开启 LVGL 显示；关闭检测模型逐帧内部 INFO 日志。
- 阈值：0.50，属于未经独立验证集标定的初始值。
- 当前固件大小：8,447,408 字节；SHA-256：`7c72cf44596dbdb5bc7d66251b74447b72ec31f1e3ed61cbb3f81a239b168900`。

## 已验证

1. 编译成功，固件在原 10 MiB 应用分区范围内。
2. 烧录到 COM3，写入后哈希验证成功。
3. 摄像头、屏幕、触摸、模型均初始化成功。
4. 在真实摄像头画面下录入 ID 1，姓名 user01。
5. 随后连续多次正确匹配 ID 1，录入验证日志中相似度约 0.74–0.84。
6. 固件更新并硬复位后，启动日志显示 db=1，list 显示 ID 1 / user01，验证持久化。
7. 正式采集 200 次有效单脸识别，并从串口恢复 200 行原始 CSV；主机重新计算的平均值、中位数、P95 与板上统计一致。

## 首轮测速

条件：特征库 1 人 / 1 条特征；20 次有效单脸预热后，测量 200 次。

| 指标 | 实测值 |
|---|---:|
| 检测平均耗时 | 29.961 ms |
| 对齐、特征模型预处理、MFN 推理、归一化平均耗时 | 161.515 ms |
| 特征匹配平均耗时 | 0.023 ms |
| 算法总耗时平均值 | 191.531 ms |
| 算法总耗时中位数 | 186.914 ms |
| 算法总耗时 P95 | 217.925 ms |
| 算法总耗时最小 / 最大值 | 184.296 / 289.508 ms |
| AI 输入准备至判定完成平均延迟 | 238.966 ms |
| 有效识别吞吐率 | 3.392 次/秒 |
| 正式样本中的 Unknown | 1 / 200 |
| 无脸 / 多脸 / 脸过小或特征异常 | 24 / 0 / 0 |

算法总耗时从检测调用前计时至匹配判定结束。AI 流程延迟从生成 AI 输入快照前计时，包含输入缩放、旋转、调度等待；不包含此前曝光、传输、PPA 预览缩放，也不包含屏幕真正显示完成。因此这里没有声称测得光学输入到屏幕结果的完整延迟。

无脸计数包含预热期间。正式有效样本中 199 条输出 ID 1，1 条输出 Unknown；由于没有独立标注和多场景测试，不将它直接写作系统准确率。未检出人脸时没有进行特征识别，单独计数。

## 后续实验

需要继续验证：未录入人员的拒识、第二人录入后的两人区分、删除功能、多轮重复、不同光照/角度/距离、不同特征库规模。CPU/PSRAM 和编译配置不变的情况下，才可直接比较不同轮次。正式写报告时，建议固定测试条件重复三轮，再进行性能优化对比。
